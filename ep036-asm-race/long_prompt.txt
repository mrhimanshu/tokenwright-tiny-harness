You are reviewing a design document for a small inference server. Read it and then summarise the three biggest risks in plain English.

The server loads a 600 megabyte language model into memory when it starts. Each request carries a prompt of between one hundred and two thousand tokens, and the server must stream the answer back one token at a time over a websocket. The team expects about forty requests per minute at peak, mostly from an internal support tool, with occasional bursts after product launches. There is no GPU in the deployment; the server runs on four virtual CPU cores in a shared cloud machine, next to a database and a queue worker, so other processes compete for the same cores and memory bandwidth.

The first version processed every prompt token one at a time, exactly like decoding. That made long prompts slow: a two thousand token prompt took many seconds before the first word of the answer appeared, and users complained that the tool felt frozen. The second version batches the prompt into large matrix multiplications, which is much faster on modern CPUs because the weights are read from memory once per batch instead of once per token. Decoding is still sequential, because every new token depends on the previous one, so decode speed is limited by how fast the machine can stream the whole model through the cache for every single token.

The team is now debating three options. Option one is to keep the current open source engine and tune thread counts. Option two is to switch to a new hand written engine that a blog post claims is a third faster at decoding, although it has no batched prompt processing and has only been tested by its author on one machine. Option three is to quantize the model further, from eight bit to four bit weights, which halves the memory traffic but may reduce answer quality on technical questions. Nobody has measured any of these options on the production hardware yet, and the launch is in two weeks. The support team cares most about the time until the first word appears, while the finance team cares about how many requests each machine can handle per minute.
